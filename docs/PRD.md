## 1. 背景与问题

### 1.1 业务场景痛点

工业质检、仓储分拣、果蔬/零件盘点、巡检取证等场景存在三类共性问题：

| 痛点 | 现状 | 后果 |
|---|---|---|
| **人眼识别效率低** | 车间/仓库靠人工盯产品挑瑕疵、数个数、做分类 | 眼疲劳、漏检、成本高、无法规模化 |
| **现场数据无法结构化** | 大量照片只是"存档"，无法自动提取信息 | 数据资产浪费，无法支撑后续分析 |
| **模型换场景就失灵** | 现有方案"一次训练定终身"，误检/漏检只能忍 | 模型无法随业务成长，越用越不准 |

### 1.2 核心洞察

> **数据质量 > 模型结构。**
> 模型的一次识别只是起点，用户的每一次修正是模型成长的养料。

真正有效的方案必须形成**闭环**：识别 → 可视化 → 校正 → 数据回流 → 重训 → 更强的识别。

### 1.3 现有方案差距

- 通用标注工具（LabelImg、CVAT）只解决"标注"，不打通"识别-校正-训练"
- 云厂商视觉 API 是黑盒，无法私有化部署、无法增量训练
- 自研 YOLO demo 停留在"画完框"，缺少数据闭环与工程化

## 2. 产品定位与一句话

**视觉飞轮 VisionFlywheel** = 以 YOLO 为核心、人工校正为飞轮动力的**自进化图像识别闭环系统**。

> **上传即识别 · 识别即可视化 · 看得不对就在图上改 · 改完的数据自动变训练集 · 训练回流后模型更强。**

## 3. 目标与非目标（MVP 边界）

### 3.1 目标（MVP 必须达成）

| # | 目标 | 衡量指标 |
|---|---|---|
| G1 | 端到端闭环可跑通 | 单用户 10 分钟内走完"上传→识别→校正→导出→训练→切换权重" |
| G2 | 校正交互可用 | 五种校正动作（确认/改标签/标误检/改框/补框）全部可操作 |
| G3 | 导出可直接训练 | 导出产物符合 ultralytics 标准，`yolo detect train` 不报错 |
| G4 | 权重热切换 | 切换默认权重不重启服务、不改代码 |
| G5 | 无 GPU 环境可跑 | torch 不可用时降级检测器，闭环依旧完整 |
| G6 | 中文友好 | 检测结果中文展示（`dog` → 「狗」） |

### 3.2 非目标（MVP 明确不做）

| # | 不做 | 原因 | 何时再做 |
|---|---|---|---|
| N1 | 多人协同实时标注 | 冲突处理复杂 | 后期版本 |
| N2 | 分割 / 关键点 / OCR | 聚焦目标检测闭环 | 按业务需求扩展 |
| N3 | 模型自动调参（AutoML） | 复杂度高，收益不明 | 远期 |
| N4 | 公有云 SaaS 多租户 | 起步私有化单实例 | 有商业需求再议 |
| N5 | 移动端 App | Web 已覆盖核心场景 | 后期 |
| N6 | 边缘设备 / 浏览器推理 | 集中部署更简单 | 有边缘部署需求再议 |
| N7 | 视频实时流（RTSP） | 抽帧视频已够用 | 后期 |
| N8 | 自动化数据增强 | 校正闭环先转起来 | M4 之后 |

## 4. 用户画像与角色

### 4.1 角色定义

| 角色 | 代号 | 关键诉求 | 典型动作 |
|---|---|---|---|
| **业务操作员** | `user` | 快速看懂识别结果、能改错的地方 | 上传图片、看结果、校正、反馈误检 |
| **算法/管理员** | `admin` | 数据闭环、模型迭代、系统配置 | 导出训练集、触发训练、切换权重、处理工单、改配置 |
| **访客** | `guest` | 只看不动 | 查看公开统计（MVP 不做） |

### 4.2 典型用户画像

**张工（业务操作员，30 岁）**
- 某电子厂质检员，每天要看 200+ 张来料照片
- 不懂英文，不懂算法，但知道什么是瑕疵
- 期望：上传照片立刻看到框、看错了能改、改完系统越用越准

**李工（算法管理员，32 岁）**
- 负责视觉算法落地，懂 YOLO、Python、Linux
- 期望：不用改代码就能切换权重；导出的数据集格式标准可直接训练；系统配置可调

## 8. 数据与资产策略

### 8.1 数据分级

| 数据 | 分级 | 备份 | 版本化 |
|---|---|---|---|
| 模型权重 `*.pt` | ⭐⭐⭐ 资产 | 必须 | `weights.dataset_version` 关联 |
| 校正数据（corrections） | ⭐⭐⭐ 资产 | 必须 | 只追加，不修改 |
| 训练集导出 `datasets/` | ⭐⭐⭐ 资产 | 必须 | `dataset_version` |
| 原始上传 `uploads/` | ⭐⭐ 数据 | 建议 | task_id 关联 |
| 结果可视化 `results/` | ⭐ 缓存 | 不必 | 可重建 |
| SQLite DB | ⭐⭐⭐ 资产 | 必须 | alembic 迁移 |

### 8.2 评估集冻结（关键）

- 每次**首次**导入一批新场景数据，随机抽 **10%** 进入 `holdout/` 评估集
- `holdout/` **永不参与训练**，只用于评估模型 mAP
- 每个 `weight` 记录训练时的 `holdout_mAP`，作为质量基线
- 切换默认权重前，必须在 holdout 上评估；mAP 显著下降则告警

### 8.3 数据集版本化

- 每次导出生成 `dataset_version = YYYYMMDD-HHMMSS-{hash}`
- 训练记录关联 `dataset_version`，实现"权重 ← 训练集 ← 校正样本"追溯链
- 后期可考虑 DVC / 自建对象存储，MVP 阶段目录约定即可

## 12. 术语表

| 术语 | 定义 |
|---|---|
| **闭环（Loop）** | 识别 → 校正 → 导出 → 训练 → 切换权重 → 再识别 的完整链路 |
| **飞轮（Flywheel）** | 闭环运转后模型持续变强的正向循环 |
| **检测框（Box / BBox）** | 目标的外接矩形，用 `(x1, y1, x2, y2)` 表示 |
| **置信度（Confidence）** | 模型对检测结果的自信程度，0~1 |
| **IoU** | 两个框的交并比，用于 NMS 抑制重叠框 |
| **NMS** | 非极大值抑制，去除重叠框 |
| **mAP** | 平均精度均值，模型质量指标 |
| **holdout / 评估集** | 永不参与训练、只用于评估的冻结数据 |
| **校正（Correction）** | 用户对检测结果的确认/修改/否决动作 |
| **审计流水（Audit trail）** | `corrections` 表，只追加不修改 |
| **数据集版本** | 每次导出的唯一标识，用于追溯 |
| **降级检测器** | torch 不可用时的内置兜底实现 |
| **热切换** | 不重启服务即可生效的权重/配置变更 |
